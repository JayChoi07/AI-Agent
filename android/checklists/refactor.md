## 컨텍스트 수집 (구현 전)
- 대상 코드를 덮는 기존 테스트 목록과 현재 통과 여부
- 스크린샷 테스트가 있는지, 기준 이미지가 저장소에 있는지
- 공개 표면(시그니처·UiState 필드·Repository 인터페이스) 사용처
- 리팩터 이유 한 줄(무엇이 읽기 어렵거나 규칙에 어긋나는지)

동작 보존이 원칙이다. 동작을 바꿔야 하면 리팩터가 아니라 별도 작업으로 분리한다. 스크린샷 기준 이미지는 record 태스크로만 갱신하며, 리팩터 중 재기록은 동작 보존 증명을 무너뜨린다 (R-30-04).
버그 수정이 섞이면 `checklists/bugfix.md`를 먼저 끝내고 리팩터를 별도로 한다 (R-00-05).

## 구현 순서
1. 현재 테스트 통과 확인 — 변경 전 기준선
   → 검증: 대상 테스트가 전부 통과, 통과 목록을 기록 (R-30-01, R-30-03)
2. 덮는 테스트가 없으면 먼저 추가
   → 검증: 추가한 테스트가 현재 구현에서 통과 (R-30-01, R-30-06)
3. 변경 — 결정 2의 파일 목록 안에서만
   → 검증: 목록 밖 파일 변경 없음, 새 추상화 없음 (R-00-05)
4. 동일 테스트 재실행
   → 검증: 1·2의 테스트가 수정 없이 그대로 통과, 스크린샷 기준 이미지 갱신 없음 (R-30-04)
5. 목표 규칙 충족 확인
   → 검증: 함수 60줄·중첩 4 이하, 체인에 이름 붙임, 계층 의존은 ui→domain→data 한 방향 (R-21-01, R-21-03, R-21-08, R-11-01)
6. ktlint·detekt·Konsist·단위 테스트 실행
   → 검증: 0 이슈 (R-31-01)
