## 구현 순서
1. 시그니처와 KDoc 계약 확정
   → 검증: 가시성·반환 타입 명시, 파라미터 순서와 기본 인자 확인, KDoc은 공개 표면에만 (R-20-10, R-21-14, R-20-14)
2. 테스트 3종 작성 — 정상·경계(빈 입력 포함)·실패. "3종"은 이 팩의 실행 기준이고 규칙 조문은 아니다
   → 검증: 클래스 이름 `<대상>Test`(R-30-06), 실패 케이스가 실제로 실패함을 먼저 확인
3. 구현
   → 검증: 한 가지 일만 하고 60줄 이하, 파라미터 5개 이하, 중첩 4 이하, 가드절 후 `return` 2개 이하 (R-21-01, R-21-02, R-21-03, R-21-04)
4. 가독성 정리
   → 검증: 조건 3개 초과는 이름 붙인 `val`로 분해, 체인이 한 문장으로 안 읽히면 중간 결과에 이름, 매직 넘버 없음 (R-21-05, R-21-08, R-21-17)
5. 코루틴·스트림 확인 (해당할 때)
   → 검증: `Dispatchers` 하드코딩 없음, `GlobalScope` 없음, `CancellationException` 다시 던짐 (R-22-02, R-22-01, R-22-10)
6. ktlint·detekt·단위 테스트 실행
   → 검증: 0 이슈, 테스트 3종 통과 (R-31-01)
