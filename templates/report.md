## 1. 문제 정의

- 주어진 과제를 어떻게 해석했는가 (해석이 갈렸던 지점과 선택 근거)
- 성공 기준을 무엇으로 정의했는가

## 2. 접근 설계

- 선택한 아키텍처/접근과 **기각한 대안** (왜 기각했는지가 사고력의 증거)
- 작업 분해: 무엇을 어떤 순서로, 무엇을 병렬로

## 3. AI Steering 방식 (핵심 섹션)

- 어떤 에이전트/도구를 어떤 역할로 썼는가 (구현/리뷰/검증 분리 등)
- 프롬프트·컨텍스트 전략: AI에게 무엇을 주고 무엇을 맡겼는가
- AI가 틀렸던 지점과 어떻게 잡았는가 (검증 루프의 실제 작동 사례)

## 4. 검증

- 성공 기준 대비 무엇을 어떻게 확인했는가 (테스트/수동 검증/교차 리뷰)
- 발견한 결함과 수정 과정
- (AI 기능이 있는 경우) 경량 eval: 고정 테스트 사례 몇 개 + 품질 기준, 프롬프트 버전별 전후 비교,
  hallucination/실패 사례와 대응 — Steering 개선을 수치·사례로 증명하는 가장 쉬운 방법
